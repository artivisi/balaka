## Highlights

Feature and correctness release. Three themes:

- **Tax filing register (issue #35).** Coretax paperwork that attaches to a *masa pajak* rather than to a journal entry — SPT Masa/Tahunan, BPE, STP, surat teguran, SP2DK, SKPLB — now has a home. Previously only transaction-linked documents (faktur pajak, bukti potong) could be stored, so there was no way to answer "has this masa been filed, when, and under which BPE" from the application.
- **Scheduled amortization could never post.** `AmortizationBatchService` runs on a `@Scheduled` thread with no security context, where `SecurityContextHolder.getContext().getAuthentication()` returns null. `JournalEntryService` dereferenced it directly, the NPE propagated, and the scheduler's catch-all logged it as a generic batch failure. Every nightly amortization run failed silently.
- **41 user manual sections were never published.** The generator matched section titles to headings fuzzily, which let one section claim another's heading. The entire PPh chapter (PPh 23 withholding, PPh 21, PPh reports) was replaced by a second copy of the PPN chapter and never rendered.

## What's New

### Tax filing register (issue #35)

New `/api/tax-filings` surface, scopes `tax-filings:read` and `tax-filings:write`:

- `GET /api/tax-filings?taxType=&year=` — list; `GET /api/tax-filings/{id}` — filing with its attached documents
- `POST /api/tax-filings`, `PUT /api/tax-filings/{id}`, `DELETE /api/tax-filings/{id}`
- `POST|GET /api/tax-filings/{id}/documents`, `GET .../{docId}/download`, `DELETE .../{docId}`

Two tables in `V005__tax_filing_register.sql`:

- `tax_filings` — one row per `(taxType, period, pembetulanNo)`. Holds the DJP-side facts with no journal entry to live on: `status` (NOT_FILED / FILED / LATE / CORRECTED), `filedDate`, `bpeNumber`/`bpeDate`, `kurangBayar`/`lebihBayar`/`nihil`, `billingCode`, `ntpn`, `paidDate`, and a nullable FK to the setoran transaction.
- `tax_documents` — tax metadata (`docType`, `docNumber`, `docDate`, `dueDate`, `amount`, `referenceNumber`) over the existing `documents` blob store, so attachments inherit the same encryption, SHA-256 checksum, and 10-year retention as transaction attachments.

A `CHECK` constraint ties period shape to tax type: `PPH_BADAN` is annual (`period_month IS NULL`), the masa types always carry a month. Uniqueness is enforced over `COALESCE(period_month, 0)` — a plain nullable column would let two PPh Badan rows share a year.

`referenceNumber` records the document chain, which is what makes an escalation readable after the fact:

```
SPT PPN 2025-04  ──▶  STP-07643        (kurang bayar tagihan)
                       └──▶ TEG-00112  referenceNumber: "STP-07643"
                              └──▶ kode billing ──▶ BPN
```

`paymentTransactionId` is deliberately optional: a nihil masa has nothing to pay, and a masa that is entirely FP-03 (BUMN pemungut) is report-only because the BUMN remits the PPN.

`GET /api/analysis/tax-summary` now carries a `filings` array alongside the tax account balances, listing every registered filing whose period overlaps the requested range. Only registered filings appear — a masa missing from the array has no record at all, which is the signal that it still needs one.

### Fixed-asset API (issues #30, #31, #32)

- `/api/fixed-assets` CRUD + `/categories`, scopes `assets:read` / `assets:write`. Registration takes exactly one acquisition source: a funding account (composes an acquisition DRAFT) or `purchaseTransactionId` (links an already-posted purchase journal without creating a new draft).
- `/api/fixed-assets/depreciation` generate / post / skip / post-all endpoints.
- Schedule-derived `periodNumber` with `uk_asset_period(id_fixed_asset, period_end)`, and scheduler catch-up so assets registered after their purchase month get every missed period generated instead of permanently skipped.

### Service authentication and retry-safe posting (issues #28, #29)

- OAuth2 `client_credentials` grant for unattended service posting: `api_clients` table, `POST /api/oauth/token`, managed under Pengaturan → API Klien.
- `Idempotency-Key` header on `POST /api/transactions` with replay semantics.

## Improvements

- **`CurrentUser` actor resolution.** Seventeen call sites dereferenced a nullable `getAuthentication()`. Replaced with two deliberate accessors: `name()` throws a clear `IllegalStateException` for request-bound code, `nameOrSystem()` returns the `system` actor for code a scheduler can reach. Two services had been papering over the same NPE with `catch (Exception _) { return "system"; }`.
- **SpotBugs is at zero findings.** Seventeen were outstanding — seven null-dereference paths in `BankReconciliationController`, nine `getCurrentUsername()` variants, and `FormulaEvaluator.read()` casting Spring's `@Nullable` target unguarded. Fixed in code rather than by exclusion.
- **User manual generator matches headings exactly.** `titlesMatch()` was case-insensitive equality *plus* substring *plus* keyword overlap; the last two silently mis-assigned content. All 268 sections are now registered with their exact heading text, and section ids are unique so `all.html` has no colliding anchors.
- **`UserManualSectionCoverageTest`** fails the build when an H2 would render nowhere, when two sections claim the same heading, or when a section id is reused.
- **Test tooling.** `run-tests.sh` holds off sleep with `caffeinate`, writes logs outside `target/`, samples memory and engine health every 30s, and captures forensics when the container engine wedges or the host suspends. Container resources are capped per-container via `ContainerResourceDefaults`.
- Spring Boot 4.1.0, actuator added, frontend libraries upgraded, redundant CVE pins dropped.

## Bug Fixes

- **Scheduled amortization never posted** — NPE on the scheduler thread, swallowed by the scheduler's catch-all. See Highlights.
- **41 user manual H2 sections never reached a published page**, across ten files, including the whole PPh chapter of the tax manual, `Koreksi Fiskal`, `Pelepasan Aset (Disposal)`, and every `Tips` / `Lihat Juga` section in the feature chapters.
- **Docker image could never start** (`fix(docker)`).
- `PUT /api/fixed-assets/{id}` ignored `autoPost`, so the flag could only be set at creation (issue #34).
- Depreciation posting always returned 409 because the `Penyusutan Aset` journal template was missing in production; the error is now surfaced instead of being reported as a conflict (issue #33).
- Dashboard dropped the leading zero in `Rp juta` amounts (`minIntegerDigits`).
- SonarCloud new-code reliability bugs, blockers, criticals, and template label accessibility findings.

## Breaking Changes

**`DELETE /api/documents/{docId}` returns 409 for a file owned by the tax filing register.** Documents are soft-deleted, and a soft-deleted row is invisible to the `tax_documents` record pointing at it, so the generic endpoint refuses rather than leaving an unresolvable link. Use `DELETE /api/tax-filings/{id}/documents/{taxDocumentId}`, which removes the metadata and the stored file together.

**Unauthenticated request-bound operations now throw `IllegalStateException` instead of `NullPointerException`.** Both were failures before and after; only the exception type and the message changed. No path that previously succeeded behaves differently.

Otherwise backward compatible: existing API endpoints, report endpoints, and the GL posting model are unchanged.

## Migration Guide

For a tenant already running 2026.06-RELEASE:

1. Standard deployment (build, restart service). Flyway applies `V005__tax_filing_register.sql` automatically — it is a new migration file, so there is no checksum work and no manual schema step. V001–V004 are unchanged.
2. **API clients need the new scopes granted explicitly.** Device tokens issued after the upgrade include `tax-filings:read` and `tax-filings:write` automatically. OAuth2 `client_credentials` clients carry a free-text scope list, so add the scopes under Pengaturan → API Klien for any service that will use the register.
3. No user action is required for the amortization fix — the next scheduled run posts normally. If nightly amortization has been failing, review the entries it generates on the first run after the upgrade before they are posted.

User manual updated: see [Register Pelaporan Pajak](https://artivisi.com/balaka/perpajakan.html#register-pelaporan-pajak) and the developer [Tax Filings API](https://artivisi.com/balaka/dev-api.html#dev-tax-filings) reference.
