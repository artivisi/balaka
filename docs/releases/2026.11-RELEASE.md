# Release 2026.11-RELEASE

## Highlights

- **Startup guards**: the application now refuses to start when it would serve with
  PII encryption disabled or with the seeded `admin`/`admin` account in place.
- **Explicit cash and bank accounts**: chart-of-account rows carry `is_cash_bank`
  instead of being inferred from the `1.1.0` code prefix.

## Breaking Changes

### Startup requires configuration

- `APP_ENCRYPTION_KEY` is mandatory. Base64 of 32 random bytes
  (`openssl rand -base64 32`). Without a valid value the process stops before the
  application context exists, so no port is opened.
- `APP_SETUP_ENABLED` has no default. Every profile states it; production sets
  `false`, which removes `/setup` from the routing table entirely.
- A deployment that still holds the seeded `admin` account is refused at startup.

### The first deploy must run the full playbook

`deploy/ansible/site.yml` writes the systemd unit with
`--spring.profiles.active=production`, runs the migrations in the `bootstrap`
profile and replaces the seeded admin. `deploy-remote-build.sh` and `deploy.sh`
only restart the existing unit; if that unit predates this release, the service
now fails to start instead of serving with the guards disabled.

### Containers without Ansible

Run the image twice: first with `--spring.profiles.active=bootstrap
--app.bootstrap.exit-after-migrate=true` plus `APP_BOOTSTRAP_ADMIN_USERNAME` and
`APP_BOOTSTRAP_ADMIN_PASSWORD`, then normally. See
`docs/admin-guide/05-updates.md`, section Menjalankan container tanpa Ansible.

## Migration Guide

1. Generate the key with `openssl rand -base64 32` and store it outside the repo.
2. Add `APP_ENCRYPTION_KEY` and `APP_SETUP_ENABLED=false` to the environment file
   of every server.
3. Run `ansible-playbook -i inventory deploy/ansible/site.yml` without `--tags app`
   for the first deployment of this release.
4. Confirm `/login` answers and the seeded `admin` account is gone.
