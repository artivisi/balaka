## Highlights

Feature, security and correctness release, the first since 2026.08-RELEASE. Schema goes from V005 to V023.

- **Tax and audit features (issues #43–#51).** Withholding on vendor and non-employee payments, the sales tax chain from invoice to faktur/receipt/bupot, deductibility flags with reviewable fiscal drafts and benefit-in-kind, payroll bonus/THR with salary-journal reconciliation, the fixed-asset register with yearly verification and disposal, evidence completeness with the audit pack, period close checks, the tax-office self-test, and the tax audit workspace.
- **Account security.** TOTP second factor, required for ADMIN and OWNER (#60). Self-service password change, forced change after an administrator sets a password, and password reset by email (#61). Remember-me login removed.
- **Authorization hardening (2026-09 test-suite audit).** Web write endpoints require their write permission; API tokens act with at most their user's current role permissions.

## What's New

### Tax and payroll
- **Withholding (#43):** payee data on vendors, PPh 21 bukan pegawai per masa, PPh 23 and PPh 26 drafts, deposit tracking, BP21 export, `/withholding` and `/api/withholding`. PPh 23/26 rates in `application.properties` are marked unverified.
- **Sales tax chain (#44):** invoice → faktur → receipt → bupot, exceptions, monthly revenue vs SPT Masa PPN DPP reconciliation, `/sales-tax-chain`, `/api/sales-tax-chain`.
- **Deductibility and benefit-in-kind (#46):** `chart_of_accounts.fiscal_treatment`, fiscal adjustments generated as `DRAFT` for review, `benefit_in_kind` recipients feeding PPh 21 and 1721-A1, seed accounts 2.1.25, 2.1.40, 3.2.03, 5.8.01–04.
- **Payroll single source (#47):** bonus/THR rows in the run, journal lines 5.8.01/5.8.02, PPh 21 refund as a debit, 1721-A1 row 8c, `/payroll/reconciliation`, alert `PAYROLL_UNPOSTED`, TER rate table corrected to the PP 58/2023 lampiran.
- **Tax self-test (#45):** `/reports/self-test`, `/api/self-test` and `/trace`, nine cross-check lines with explanations.
- Coretax object codes remapped to the e-Bupot list (V017). Annual PPh 21 deducts JHT + JP; JP ceiling by period.

### Assets, evidence, close and audit
- **Fixed-asset register (#49):** brand, model, custodian, condition, photo; yearly checklist at `/assets/verification`; disposal record with a DRAFT journal and tax effect.
- **Evidence completeness (#48):** evidence rules per account/template, missing-evidence report, contract register, monthly bank statement archive with 10-year retention, yearly audit pack ZIP, `/api/evidence`.
- **Period close checks (#50):** checklist on fiscal period and year-end pages, `/api/close-checks`, shareholder current account statement, alert `LIABILITY_UNMOVED`.
- **Tax audit workspace (#51):** `/tax-audit` year view traced to ledger lines and source documents, append-only inquiry cases with disclosure ZIP, archive ZIP + manifest import with full-text search, evidence required at posting from `company_config.evidence_required_from`.
- **Multi-file upload (#57):** several transaction documents in one request, with a per-file outcome.

### Account security
- **TOTP second factor (#60):** RFC 6238 (SHA-1, 6 digits, 30 s), single use per time step, 5 failed attempts per 15 minutes lock verification, ten single-use recovery codes stored as SHA-256, administrator reset from the user page. `app.mfa.enabled=true` and `app.mfa.required-roles=ADMIN,OWNER` by default; other users may enrol under Verifikasi Dua Langkah. The secret is encrypted with `APP_ENCRYPTION_KEY`.
- **Self-service password change (#61):** `/account/password` for every role (key icon beside logout). Requires the current password; the new one must differ.
- **Forced change (#61):** a password set by an administrator (new user, or Ubah Password on the user page) must be changed at the next login. Until then the web session reaches only the change page, logout and the MFA pages; API calls get `403 password_change_required`. User list and detail show "Wajib ganti password".
- **Revocation (#61):** every password change revokes the user's device tokens and ends their other web sessions (`/login?expired`).
- **Reset by email (#61):** "Lupa password?" on the login page sends a single-use link valid 30 minutes, stored as SHA-256; a newer request supersedes older links; identical answer for unknown addresses; limited per IP and per account; link built from the configured base URL. Administrators can send the reset email from the user page. Off by default (`app.password-reset.enabled`); when off the link is hidden and the pages answer 503. Supports SMTP with login or an IP-authenticated relay (Google Workspace SMTP relay).

### Configuration
- Document storage path and forwarded headers from the environment (#58); `server.forward-headers-strategy=native`.

## Improvements
- Web write endpoints require their write permission; previously many needed only `*_VIEW`, and BOM, production, milestone, payment term, document and data export controllers had no check.
- API tokens: effective authority = token scopes ∩ the user's current role permissions, evaluated per request; tokens of deactivated users return 401. New scopes `payroll:write`, `tax-export:write`, `templates:read/write`, `bank-recon:read/write`; `drafts:*` enforced; `POST /api/transactions` requires `transactions:post`. Browser sessions cannot call `/api/**`; CSRF is waived only for Bearer requests.
- API errors carry the documented `error` code and service message (`CONFLICT`, `INVALID_REQUEST`, `CONFIGURATION_ERROR`).
- Journal lines keep an explicit per-transaction order (V007).
- Backups fail loudly on stale or broken archives; manifest is valid JSON (#36, #37).
- nginx overwrites `X-Forwarded-For` instead of appending (rate-limit key spoofing).
- SpotBugs at 0 findings; Spring Boot 4.1.2.

## Bug Fixes
- PPh Badan computed on PKP after fiscal loss compensation; fiscal loss no longer compensable in or before its origin year.
- Bank reconciliation: book-only items split by debit/credit; items and transactions must belong to the reconciliation (#38).
- Analysis receivables/payables use the accounts configured in company settings (were hard-coded 1.1.04 / 2.1.01).
- Duplicate employee NPWP and duplicate company bank account numbers were accepted whenever `APP_ENCRYPTION_KEY` was set: the equality query compared against randomly-IV'd ciphertext. Now compared on decrypted values.
- `company_bank_accounts.account_number` was `VARCHAR(50)`, too narrow for an encrypted value (V018).
- `GET /api/payroll?year=` filtered after paging, so a year with newer runs above it returned an empty or partial page.
- Default dates used the UTC date (wrong between 00:00 and 07:00 WIB); edit forms posted to another record after a rejected code change; account picker could select a stale result; Alpine components re-created after every HTMX swap.
- Oversized upload returns 413.
- Cash and bank accounts are flagged on the account (`chart_of_accounts.is_cash_bank`, V023) instead of selected by `account_code LIKE '1.1.0%'`, which also matched receivables, prepaid expenses and input VAT and overstated cash in the cash flow statement and on the dashboard. The migration flags every account the old selector counted (active non-header ASSET under `1.1.0%`) plus every account linked to a company bank account, so no report changes at deploy; a flagged account that is not cash is unflagged in the account form. Linking or releasing a bank account maintains the flag (#56).

## Breaking Changes
- **MFA required for ADMIN and OWNER.** They are sent to enrolment at the next login. `APP_ENCRYPTION_KEY` must be set, or enrolment fails.
- **Remember-me removed.** Every session starts with a password login; sessions end after 15 minutes idle.
- **`app.storage.documents.path` has no default** (`APP_DOCUMENT_STORAGE_PATH`). Ansible sets `/opt/<app_name>/documents`; the Docker image uses `/opt/app/documents`.
- **Administrator-set passwords are temporary** (see Forced change). Existing accounts are not flagged.
- **User email addresses are unique, case-insensitive.** V022 stops and lists the addresses if two active users share one. Blank addresses are stored as NULL.
- **Write permissions and API scopes** as listed under Improvements. Existing device tokens receive the new scopes; OAuth2 API clients do not.
- **Journal export** (`20_journal_entries.csv`) has a trailing `line_order` column; exports made before this release no longer import.
- **Chart of accounts export** (`02_chart_of_accounts.csv`) has a trailing `is_cash_bank` column. A file without it still imports, with 1.1.01–1.1.03 flagged.
- **V017** stops if any stored tax object code is `24-104-99` or `21-100-09`; recode those rows first.
- **Deploys no longer reset the administrator password.** `deploy.yml` and `deploy-remote-build.sh` used to overwrite the `admin_username` account's password with `admin_password_plain` on every run. They now create that account only when it does not exist, flagged to change the password at the first login, and leave an existing account alone. A forgotten administrator password is recovered by email reset or by another administrator.
- **MFA on demo instances** must be switched off with `app_mfa_enabled: false` in their group_vars (role accounts share a published password). The template emits `app.mfa.enabled` / `app.mfa.required-roles` only when `app_mfa_enabled` / `app_mfa_required_roles` are set.

## Migration Guide

For artivisi (currently 2026.08-RELEASE, schema V005). Rehearsed on a copy of the production database on 2026-11-18: V006–V022 apply after step 2, and the resulting schema is identical to a fresh install.

1. **Back up** the database and `/opt/aplikasi-akunting/documents`.
2. **Correct two data conditions** that V008 and V012 refuse, in one transaction:
   ```sql
   BEGIN;
   -- Every account in production has is_header = false, including the 19 parents. V008 refuses to add
   -- seed accounts under a non-header. Mark the parents that hold no postings as headers (expect 18 rows).
   -- 5.1.08 Beban Transportasi has postings and children and stays a leaf.
   UPDATE chart_of_accounts p SET is_header = TRUE
    WHERE EXISTS (SELECT 1 FROM chart_of_accounts c WHERE c.id_parent = p.id)
      AND NOT EXISTS (SELECT 1 FROM journal_entries j WHERE j.id_account = p.id);
   -- An old "Pelepasan Aset Tetap" template from an earlier seed import has no lines and no transactions.
   -- V012 creates the real template under that name (expect 1 row).
   UPDATE journal_templates SET template_name = 'Pelepasan Aset Tetap (lama, tanpa baris)', active = FALSE
    WHERE template_name = 'Pelepasan Aset Tetap';
   COMMIT;
   ```
3. **group_vars** (deploy repo, `clients/artivisi/group_vars/all.yml`): add the password reset settings. artivisi uses the Google Workspace SMTP relay, which admits the server by IP (SPF, DKIM and DMARC for artivisi.com verified on 2026-11-18):
   ```yaml
   password_reset_enabled: true
   password_reset_from: "noreply@artivisi.com"
   smtp_host: "smtp-relay.gmail.com"
   smtp_port: 587
   smtp_auth: false
   ```
   `document_encryption_key` must already be set (it is used for PII and the MFA secret).
4. **Deploy with the full playbook** (`deploy.sh artivisi`), not `deploy-remote-build.sh`: the application properties template changed (document storage path, mail, EHLO name). Flyway applies V006–V022. The existing administrator account keeps its current password.
   Before starting the new jar, remove `--spring.config.location=...` from the `ExecStart` of `/etc/systemd/system/aplikasi-akunting.service` and run `systemctl daemon-reload`. That option replaces the packaged `application.properties`, and 2026.11 fails to start without the defaults it holds (`app.mfa.max-attempts` first). The service runs in `/opt/aplikasi-akunting`, where Spring Boot loads `./application.properties` over the packaged file. `deploy.yml` does not rewrite the unit file; `site.yml` installs the corrected template. On artivisi this was found at the first start and fixed by switching to `--spring.config.additional-location`, which behaves the same.
5. **After start:**
   - The administrator logs in, enrols the authenticator and stores the recovery codes.
   - Configure receivable and payable accounts in company settings if the dashboard KPI widget asks for them.
   - Grant new scopes to OAuth2 API clients under Pengaturan → API Klien if they use payroll, fiscal adjustment, template, bank reconciliation or draft endpoints.
   - Request a password reset for a test account and confirm the email arrives.
6. Tag the deployed commit `2026.11-RELEASE`.

## Known Issues
- nginx on artivisi has `client_max_body_size 20M`, while the archive import accepts ZIPs up to 100 MB; larger imports get 413 from nginx. Raise `nginx_client_max_body_size` if archive import is used.
- Sessions are held in memory; MFA attempt counters and reset rate limits are per instance.
- `5.1.08 Beban Transportasi` holds postings and has child accounts; reports list both levels.
- Open review items carried over: see `docs/test-suite-audit-2026-09.md`, Open Decisions.
