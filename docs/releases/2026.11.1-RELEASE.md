## Highlights

Security and access patch on top of 2026.11-RELEASE. No schema change: the schema stays at V023.

- **Production startup guards (PR #55).** A production instance refuses to start without a valid encryption key, while the seeded `admin` account exists, or with an empty user table and setup disabled.
- **Swagger UI and the OpenAPI spec require authentication.** API clients obtain a token before reading the spec.
- **EMPLOYEE role lands on its own pages.** Employees land on their payslips with a Layanan Mandiri menu instead of a 403 on the dashboard.

## What's New

### Startup guards
- `APP_ENCRYPTION_KEY` must be a Base64-encoded 32-byte key; without it the application stops before opening its port.
- `app.setup.enabled` has no default; `APP_SETUP_ENABLED` must be stated.
- Startup fails while the seeded `admin` account is in the database, or when the user table is empty and setup is disabled.
- Guards apply to every profile except `dev`, `test`, `functional`, and `bootstrap` run with `--app.bootstrap.exit-after-migrate=true`.
- Containers without Ansible create their administrator with a bootstrap run (`APP_BOOTSTRAP_ADMIN_USERNAME` / `APP_BOOTSTRAP_ADMIN_PASSWORD`, profile `bootstrap`). Steps: `docs/admin-guide/05-updates.md`, "Menjalankan container tanpa Ansible".

### Employee self-service
- `/` redirects by role: `DASHBOARD_VIEW` to `/dashboard`, otherwise `OWN_PAYSLIP_VIEW` to `/self-service/payslips`. Login, forced password change and the MFA step use it.
- Sidebar group Layanan Mandiri (Slip Gaji Saya, Bukti Potong PPh 21, Profil Saya) for every role. Groups with no permitted link are hidden, so an EMPLOYEE sees Layanan Mandiri and Pengaturan only.

## Improvements
- `deploy.yml` runs migrations in a `bootstrap` profile before starting the service, and restores the previous jar, `application.properties` and systemd unit when a step after the stop fails.
- Accessibility: labels on tax audit, asset verification and archive form controls; header rows on contract, sales tax chain and disclosure tables; Escape closes the inventory and payroll export dropdowns.

## Bug Fixes
- `/clients/search` and `/vendors/search` required only a login; they now require `CLIENT_VIEW` / `VENDOR_VIEW`. An EMPLOYEE could list every client and vendor name.
- The "Portal Karyawan" sidebar link pointed to a page that does not exist; removed.
- Error pages link to `/` instead of `/dashboard`.

## Breaking Changes
- **Startup guards.** An instance upgraded without an encryption key, with the seeded `admin` account, or without `APP_SETUP_ENABLED` does not start. See Migration Guide.
- **`/v3/api-docs` returns 401 without a Bearer token or a web session; `/swagger-ui` redirects to `/login`.** AI clients and scripts complete the device flow (`/api/device/code`, `/api/device/token`) first, then read the spec with `Authorization: Bearer <token>`.

## Migration Guide

From 2026.11-RELEASE:

1. Set `APP_ENCRYPTION_KEY` (already required by 2026.11 for MFA) and `APP_SETUP_ENABLED=false`.
2. **Ansible:** the host needs the `acl` package for the bootstrap migration step (`become_user`); the `common` role installs it, or `apt install acl`. Then run `deploy.yml`. It replaces the seeded `admin` with `admin_username` if it is still there.
3. **Container without Ansible:** run the bootstrap container once with `APP_BOOTSTRAP_ADMIN_USERNAME` / `APP_BOOTSTRAP_ADMIN_PASSWORD`, then start normally. `docs/admin-guide/05-updates.md`.
4. Update API clients that fetch `/v3/api-docs` anonymously to authenticate first.

artivisi and the demo instances run this code since 2026-11-21, except the accessibility fixes.

## Known Issues
- `deploy.yml` does not apply the `nginx` role. The `X-Forwarded-For` overwrite listed in 2026.11 needs `site.yml` or a manual edit of `/etc/nginx/snippets/proxy-params.conf`; artivisi and demo were corrected by hand on 2026-11-20.
- Carried over from 2026.11: archive import above nginx `client_max_body_size` gets 413; sessions and rate-limit counters are per instance.
